# /review behavior inventory

The behaviors of `home/dot_claude/skills/review/SKILL.md` that the people
and programs below depend on, where in the skill each one comes from, and
the case that covers it, so a change to the skill can be checked against
this list before its tests run.

Who depends on these behaviors:

- **caller**: the session that runs `/review`, then commits or pushes on
  its result
- **user**: answers the dialog and reviews the work at the PR
- **review-gate**: `home/dot_local/bin/executable_review-gate`, which reads
  the triage file and refuses unreviewed commits and pushes
- **/pr**: `home/dot_claude/skills/pr/SKILL.md`, which runs
  `/review branch` and acts on its summary
- **global CLAUDE.md**: its Git section tells every session how to act on
  `/review`'s output

A case name in the last column means a case in `cases/` tests that
behavior. "none" means no case does; the reason follows when it matters.

## Not tested, and why

- Behaviors that need the model's own hesitation or wording (hesitation,
  hedging phrases, dismissive labels) can't be set up as facts; a case
  would test the scenario, not the skill.
- Deterministic steps (git commands, auto-detection by path or token, the
  verifier ladder) are better checked by reading a diff of the change
  against this inventory than by a model call.
- The full final summary format (Step 14 item 4) has many optional
  sections; a case would need a large scenario for one string. Check it by
  reading.
